Lumina 使用指导

版本：当前工程代码（PySide6 桌面应用）

1. 工程简介

Lumina 是一个照片库管理工具。核心目标是：把照片统一整理到照片库目录中，并维护一个 SQLite 数据库用于去重、标签管理和检索。

  • 照片库按时间组织：年/月/文件名。
  • 数据库以 md5 为主键，用于快速判断是否已入库。
  • 支持手工标签与自动标签（AI 模型）并可检索。

2. 环境准备与启动

2.1 安装依赖

pip install -r requirements.txt

2.2 启动应用

python -m app.main
提示：如果使用 AI 自动打标，需要本地模型服务可用（默认配置为 Ollama）。 不使用 AI 时，也可以通过导入页的选项允许无模型导入。

3. 页面功能说明

3.1 Page 1 - Settings（设置）

  • 选择照片库根目录（必须存在且可写）。
  • 数据库文件路径会自动归一化为：<library_root>/lumina.db。
  • 可进行数据库检查（DB 与磁盘文件一致性校验）。
  • 可配置 AI 服务地址、模型，并检查连接/加载状态。

3.2 Page 2 - Import（导入）

  • 支持添加文件或目录，批量导入图片。
  • 按 MD5 去重：若数据库已存在同 MD5，标记为 duplicate。
  • 捕获时间优先来自元数据；无元数据则尝试文件名推断；仍失败则跳过并记录。
  • 导入目标结构：YYYY/MM/IMGYYYYMMDDHHMM_XXXXXXXX.EXT。
  • 支持“预导入（Pre-Import）”：先准备、检查、修订，再正式导入。
  • 支持按目录规则补充标签和时间回退值。

3.3 Page 3 - Tagging（标签处理）

  • 支持批量匹配标签（候选标签集合 + AI 判定）。
  • 支持批量重算 autotags（自动标签）。
  • 支持基于参考人物图的姓名标签补充。

3.4 Page 4 - Search（检索与展示）

  • 支持按一级/二级目录过滤（如年/月）。
  • 支持按 tags + autotags 搜索。
  • 支持预览、缩放、旋转、保存、复制、删除。
  • 支持在结果表格中编辑部分字段并回写数据库。

4. 照片入库规则（关键约定）

  1. 源文件计算 MD5。
  2. 如果 MD5 已存在于库 DB，则不重复入库。
  3. 获取 capture time（元数据优先，文件名推断次之，目录规则回退可选）。
  4. 生成目标路径并移动文件到照片库。
  5. 写入/更新数据库记录（路径、时间、tags、autotags）。

示例目标路径： 2000/01/IMG200001021234_12345678.JPG

5. 常见问题

  • 导入按钮不可用：先在 Page 1 设置有效照片库目录并保存。
  • 提示模型不可用：检查模型服务地址、模型是否已加载，或开启“允许无模型导入”。
  • 文件被跳过：通常是无法获得 capture time，请在预导入中补时间后重试。

6. 开发者快速入口

  • 应用入口：app/main.py
  • 主窗口与导航：app/ui/main_window.py
  • 导入主逻辑：app/services/photo_import_service.py
  • 预导入逻辑：app/services/preimport_service.py
  • 数据库访问层：app/db/repository.py
  • 主库 Schema：app/db/schema.sql

7. 照片库数据库说明（供其他工程复用）

这是给其他项目复用同一个 DB 文件时最重要的约定。 Lumina 主数据库默认位于照片库根目录下：<library_root>/lumina.db。 其他工程只要遵守以下结构和语义，就可以共享这一个数据库文件。

7.1 主表：photos

字段 类型 说明
md5 TEXT PRIMARY KEY 照片文件内容 MD5，作为唯一主键（去重依据）。
relative_path TEXT NOT NULL 照片相对路径（相对于 library root），例如 2024/08/IMG202408151230_12345678.JPG。
capture_time TEXT NULL 拍摄时间（ISO 字符串）。
tags TEXT NOT NULL 手工标签 JSON 数组字符串，默认 []。
autotags TEXT NOT NULL 自动标签 JSON 数组字符串，默认 []。

7.2 与文件系统的对应关系

  • absolute_path = library_root / relative_path
  • 如果文件被重命名或移动，需同步更新 relative_path。
  • 如果文件被删除，建议同步删除该条 DB 记录。

7.3 跨工程复用建议

  • 写入前先做 MD5 判重，避免主键冲突。
  • tags/autotags 按 JSON 数组读写，保持 UTF-8 文本。
  • 不要把绝对路径写入 DB；统一使用 relative_path。
  • 如需扩展字段，保持向后兼容，避免破坏现有查询和导入逻辑。

说明：工程中还存在 preimport.db（预导入任务状态库），它是流程缓存，不是照片主库。 与其他工程共享照片数据时，应共享 lumina.db + 照片库目录。
